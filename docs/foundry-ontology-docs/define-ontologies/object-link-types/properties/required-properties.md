# 必填属性（Required properties）

> 本文为 [Palantir 官方文档](https://www.palantir.com/docs/foundry/object-link-types/required-properties/)的非官方中文翻译，仅供学习参考。原文 © 2026 Palantir Technologies Inc. 保留所有权利。

必填属性是必须具有值的对象类型属性。你可以使用这种对象类型属性来验证不存在该属性为空值（null）的对象；如果是数组属性，则验证不存在空数组。此验证适用于来自支撑数据源的数据以及通过动作进行的编辑。

## 必填属性概览

处理必填属性时，请记住以下几点：

- **验证在数据编入对象时进行：** 对空值的检查发生在支撑数据源被索引编入对象存储（Object Storage）时。这意味着，如果支撑必填属性的列包含空值，本体修改本身仍会成功。
- **数组属性不能为空：** 将数组属性设置为必填可确保至少存在一个数组项。
- **通过动作进行的更改在应用时验证：** 如果你尝试通过动作向属性写入 null 或空值，动作将执行失败。
- **仅在 Object Storage v2 中可用：** 必填属性仅由使用对象存储 v2（Object Storage v2）的对象类型支持。

### 创建必填属性

1. 导航到 **Ontology Manager**。
2. 选择对象类型，然后选择要设为必填的属性。
3. 选择 **Create Property**（创建属性）并填写所需的详细信息，包括属性名称、类型和描述。
4. 在 **Configuration**（配置）部分，打开 **Required**（必填）开关。
5. **Save**（保存）你对本体的更改，并等待重新索引完成。

请注意，如果该属性的支撑列上当前存在任何空值，重新索引将失败。要解决此问题，你必须更新支撑数据源使该列不再包含空值，或者取消将该属性设为必填。

### 允许空数组的必填属性

你可以将必填属性配置为允许空数组。这意味着该属性仍会拒绝 null 值，但会接受空数组。这对于永远不能为 null、但可以配置为允许空数组的强制控制属性非常有用。详细了解[强制控制属性](https://www.palantir.com/docs/foundry/object-link-types/mandatory-control-properties/)。

需要特别注意的是，动作会向任何映射到参数但该参数未设置的属性写入空数组。这意味着，如果你有一个允许空数组的必填属性，并且在动作中将该参数留空，动作将成功并向该属性写入空数组。如果你不希望出现这种行为，并希望强制用户始终通过动作为该属性设置值，则不应在必填属性上允许空数组。

### 具有多个支撑数据源的对象类型的必填属性

你有时可能会遇到这样的情况：由多个数据源支撑的对象类型，其必填属性中出现空值。当某个对象的记录存在于某些数据源中，但在提供该必填属性的数据源中缺失时，就会发生这种现象。

以下示例说明了这种行为。假设有一个 `Movie` 对象类型，具有两个支撑数据源和一个必填的 `Genre` 属性。

**数据源 1**

| 电影 ID | 标题 | 票房 | 上映地区 |
| --- | --- | --- | --- |
| 101 | 《冒险开始》 | 200m | [“USA”, “Canada”, “UK”] |
| 102 | 《城市之恋》 | 75m | [] |
| 103 | 《银河之战》 | 500m | [“USA”, “UK”, “Australia”] |

**数据源 2**

| 电影 ID | 预算 | 类型（必填） | 导演 |
| --- | --- | --- | --- |
| 101 | 50m | 冒险 | Michael John Smith |
| 102 | 20m | 爱情 | Jane Doe |
| 103 | 150m | 科幻 |  |

如果一部新的 `Movie` 被添加到两个支撑数据源中但没有提供 `Genre` 值，它将无法编入本体索引。

然而，假设只有数据源 1 中存在新 `Movie` 对象的行。

**数据源 1**

| 电影 ID | 标题 | 票房 | 上映地区 |
| --- | --- | --- | --- |
| 101 | 《冒险开始》 | 200m | [“USA”, “Canada”, “UK”] |
| 102 | 《城市之恋》 | 75m | [] |
| 103 | 《银河之战》 | 500m | [“USA”, “UK”, “Australia”] |
| 104 | 《幸福结局》 | 150m | [“UK”, “FRANCE”] |

**数据源 2**

| 电影 ID | 预算 | 类型（必填） | 导演 |
| --- | --- | --- | --- |
| 101 | 50m | 冒险 | Michael John Smith |
| 102 | 20m | 爱情 | Jane Doe |
| 103 | 150m | 科幻 |  |

上面的示例将成功编入本体索引，尽管生成的对象在该必填属性上没有值。

| 属性 | 值 |
| --- | --- |
| 电影 ID | 104 |
| 标题 | 《幸福结局》 |
| 票房 | 150m |
| 上映地区 | [“UK”, “FRANCE”] |
| 预算 |  |
| 类型（必填） |  |
| 导演 |  |

这同样适用于通过动作编辑创建的对象。如果 `Movie` 对象只包含与数据源 1 中列相关联的属性，则可以成功创建或修改。但是，如果动作向对象添加了来源于数据源 2 的属性（例如 `Budget`），则该动作将无效并执行失败。这是因为该对象现在将存在于数据源 2 中，因此必须设置 `Genre`。
