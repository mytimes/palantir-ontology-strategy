# 强制控制属性（Mandatory control properties）

> 本文为 [Palantir 官方文档](https://www.palantir.com/docs/foundry/object-link-types/mandatory-control-properties/)的非官方中文翻译，仅供学习参考。原文 © 2026 Palantir Technologies Inc. 保留所有权利。

强制控制属性是对象类型属性，允许对存储在对象中的数据进行细粒度访问控制。你可以使用强制控制属性来限制对给定对象同一数据源中所有其他属性的访问，使这些属性仅对满足强制控制的用户可见。

**注意：** 强制控制属性**仅在 Object Storage v2 上可用**。

## 如何使用强制控制属性

1. 首先，创建由标记支撑的受限视图（RV）。详细了解[创建由标记支撑的受限视图](https://www.palantir.com/docs/foundry/security/restricted-views/#create-marking-backed-restricted-views)。
2. 导航到 Ontology Manager。
3. 选择要限制其属性访问的对象类型，然后创建或选择你要设置为强制控制属性的属性。
4. 在属性侧边栏上，确保该属性映射到受限视图上对应的**标记列（marking column）**。
5. 将属性类型的基础类型设置为 **Mandatory Control**（强制控制）。
  1. 默认情况下，强制控制属性支持**标记（markings）**和/或**组织（organizations）**来限制访问。
  2. 如果你启用了 CBAC，你将可以选择基于**密级（classification）**的强制控制。
6. 在数据源上选择 **Allowed markings**（允许的标记）和/或 **Allowed organizations**（允许的组织）。对于密级，选择 **Max classification**（最高密级）。
7. 如果对象类型有多个数据源，请为其他每个数据源选择一个强制控制属性，以保护它们的属性。
8. 将更改保存到本体，并等待重新索引完成。

## 强制控制属性的类型

可以在属性上设置三种类型的强制控制：

- [标记](#标记)
- [组织](#组织)
- [密级](#密级)

### 标记

标记是强制控制，通过要求用户拥有特定标记才能访问数据来限制访问。如果资源具有多个标记，用户必须拥有全部标记才能访问该资源。详细了解[标记](https://www.palantir.com/docs/foundry/security/markings/)。

要使用标记，你需要提供一组允许的标记。只有此集合中的标记才会被允许出现在数据源上的任何强制控制属性中。

### 组织

组织是访问要求，在用户组和资源之间实施严格的隔离。每个用户只能是一个组织的*成员*，但可以是多个组织的*访客成员*。要访问标记了组织的数据，用户必须是该组织的成员。如果资源具有多个组织，用户必须是应用于该资源的至少一个组织的成员。详细了解[组织](https://www.palantir.com/docs/foundry/security/orgs-and-spaces/#organizations)。

要使用组织，你需要提供一组允许的组织。只有此集合中的组织才会被允许出现在数据源上的任何强制控制属性中。

标记和组织可以在同一个强制控制属性上一起使用。在这种情况下，用户必须满足所有标记并且是至少一个组织的成员才能访问该资源。

### 密级

密级标记是用于保护敏感政府信息的强制控制。它们用于在信息敏感度以分层方式定义的情况下限制对敏感信息的访问。每个用户只能访问密级等于或低于其自身密级的数据。

只有在你的注册实例上启用了 CBAC 时，你才能配置 CBAC 标记。详细了解 [CBAC（基于密级的访问控制）](https://www.palantir.com/docs/foundry/security/classification-based-access-controls/)。

要使用密级，你需要提供最高密级。只有满足此最高密级的标记才会被允许出现在数据源上任何基于密级的强制控制属性中。

密级不能与标记或组织在同一个强制控制属性上一起使用。

## 数据源级授权

强制控制属性保护同一数据源中的所有其他属性。对于具有单个数据源的对象类型，这意味着用户只有在满足强制控制属性中的值时才能查看对象。

但是，对于多数据源支撑的对象类型（MDO），每个数据源可以有自己的强制控制属性。只有由特定数据源支撑的属性才会受到该数据源中强制控制的保护。

这意味着用户可能仅有权查看对象上的一部分属性。在这种情况下，用户只能看到从这些数据源映射的属性。向用户显示对象实例时，其他属性将显示为 null。

为了有效使用强制控制属性，支撑数据源的结构应使只有应共享同一强制控制的属性才位于同一数据源中。

## 验证

对强制控制属性实施以下验证：

- 强制控制属性必须映射到**受限视图**上的**标记列**。强制控制是通过用受限视图支撑对象类型来实施的，该受限视图具有一项策略，要求用户满足映射列中的标记才能查看某一行。有关更多信息，请参阅[受限视图](https://www.palantir.com/docs/foundry/security/restricted-views/)。
- **强制控制属性必须是必填的。** 这可确保如果数据源上存在具有强制控制属性的对象，则必须定义强制控制，以帮助维护数据一致性和完整性。所有强制控制属性不得为 null。但是，标记和组织值可以设置为空数组。在这种情况下，所有用户都将满足标记要求并能够查看该行。详细了解[必填属性](https://www.palantir.com/docs/foundry/object-link-types/required-properties/)。
  - 如果你想向已经有编辑内容的仅编辑对象类型添加强制控制属性，你无法直接创建该属性，因为强制控制属性不能为空。解决方法是：
    1. 添加一个可为空的字符串数组属性。
    2. 使用[动作](https://www.palantir.com/docs/foundry/action-types/overview/)回填其值。
    3. 将该属性的基础类型更改为 **Mandatory Control**。
- 每个包含强制控制属性的数据源都必须定义一个约束，规定可以向这些属性添加哪些值。这些约束的形式包括：针对基于密级的强制控制的最高密级，或一组允许的标记和/或允许的组织。对强制控制属性所做的任何编辑，以及从支撑数据集获取的值，都必须遵守数据源上设置的约束。
  - 此约束在对象存储层面实施，因此即使你可以使用 Ontology Manager 保存违反此约束的对象类型，如果数据集中的现有值不满足约束，或者数据集中的值被更新为包含强制控制的无效值，该对象类型也将无法编入索引。此外，任何试图将强制控制属性设置为无效值的编辑都将被拒绝，动作将无法提交。
  - 这些允许的标记、允许的组织或最高密级将用于标记从此对象类型物化的任何导出数据集。这确保只有能够查看该对象类型上所有行的用户才能查看物化数据集。

请注意，强制控制属性默认设置为 `Hidden`（隐藏）。这是因为强制控制属性旨在用作其他字段的标记，因此通常不需要强制控制属性出现在对象视图或表格中。但是，如果需要，仍可以启用强制控制属性的可见性。

## 动作中的强制控制

你可以向动作类型添加强制控制参数。这可以是标记参数，或者在启用 CBAC 时是密级参数。目前不支持组织参数。

强制控制参数通常用于在动作创建的对象上设置强制控制属性。在这种情况下，提供的值必须遵守该属性的允许值；如果提供了无效值，动作提交将失败。

对于基于密级的强制控制参数，你还可以在参数级别添加最高密级。这是一种动作类型验证，因此如果提供的值不满足最高密级，将阻止动作提交；而不是依赖数据源验证——数据源验证会允许动作提交但无法完成。

由动作创建的对象将由强制控制属性的提供值保护，就像从支撑数据源派生的对象一样。

## Marketplace 用法

具有强制控制属性的对象类型和具有强制控制参数的动作类型可以通过 Marketplace 打包和安装。

打包具有强制控制属性的对象类型时，允许的标记或最高密级会被声明为该产品的安装输入。

类似地，如果打包具有基于密级的强制控制参数且设置了最高密级的动作类型，该最高密级会被声明为安装输入。

安装产品时，系统会提示你为每个强制控制属性选择允许的标记或最高密级。所选值将在安装时设置为强制控制属性的允许标记或最高密级。

![在 Marketplace 安装期间选择强制控制输入](https://www.palantir.com/docs/resources/foundry/object-link-types/marking-inputs-install.png?width=800)

请注意，打包具有相同值的多个强制控制属性和/或参数时，只会声明一个强制控制输入。
