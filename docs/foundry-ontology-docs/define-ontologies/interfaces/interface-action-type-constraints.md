# 接口动作类型约束（Interface action type constraints）

> 本文为 [Palantir 官方文档](https://www.palantir.com/docs/foundry/interfaces/interface-action-type-constraints/)的非官方中文翻译，仅供学习参考。原文 © 2026 Palantir Technologies Inc. 保留所有权利。

> **ℹ️ 提示：Beta（测试版）**
>
> 接口动作类型约束处于开发的 [beta（测试版）](https://www.palantir.com/docs/foundry/platform-overview/development-life-cycle/)阶段，可能在你的注册实例上不可用。在活跃开发期间，功能和平台支持可能会发生变化。

接口动作类型约束定义了实现某个接口的各对象类型之间共有的、预期的动作能力。该约束描述了动作面向用户的含义、API 名和参数形状。每个实现对象类型随后可以将该约束映射到该对象类型上的一个具体动作类型。

例如，`Ticket`（工单）接口定义了一个 `Create ticket`（创建工单）动作类型约束。`Bug`（缺陷）对象类型用 `Create bug`（创建缺陷）动作类型满足该约束，`Feature request`（功能请求）对象类型用 `Create feature request`（创建功能请求）动作类型满足它。两个动作类型实现了相同的接口级能力，尽管具体动作逻辑是各对象类型特有的。

![接口动作类型约束选项卡。](https://www.palantir.com/docs/resources/foundry/interfaces/iatc-config-page.png?width=800)

接口动作类型约束不定义动作执行逻辑、提交条件、副作用或表单布局。要配置这些行为，请在满足该约束的具体动作类型上进行配置。有关作用于接口对象的动作规则的更多信息，请参阅[接口上的动作](https://www.palantir.com/docs/foundry/action-types/actions-on-interfaces/)。

目前，动作类型约束在描述满足约束的动作类型必须如何行为方面表达能力有限。请使用约束描述告知应用构建者满足约束的动作类型应当做什么，包括预期的编辑、副作用、提交行为，或约束模型未强制实施的其他语义要求。表达能力更强的行为约束正在活跃开发中。

## 动作类型约束

动作类型约束定义了接口级动作能力的各项参数。这些参数包括：

- **显示名：** 动作类型约束面向用户的名称。
- **描述：** 用户可读的描述，说明满足约束的动作类型应当做什么。
- **API 名：** 在代码和平台配置中引用该约束时使用的 API 名。
- **参数约束：** 满足约束的动作类型必须暴露的参数。
- 该动作类型约束是否为对象类型实现中的必填项。

如果动作类型约束是必填的，每个实现该接口的对象类型都必须将该约束映射到一个具体动作类型。可选的动作类型约束可以在实现对象类型支持该能力时进行映射，但在该能力不适用时可以跳过。

![动作类型约束配置对话框。](https://www.palantir.com/docs/resources/foundry/interfaces/iatc-config-dialog-set.png?width=500)

## 参数约束

参数约束定义了满足约束的动作类型必须提供的动作参数的形状。每个参数约束包括：

- **类型：** 参数类型，例如字符串、时间戳、对象引用、接口引用、对象集、附件、媒体引用或结构体。
- **单值或列表值：** 该参数接受单个值还是值列表。
- **显示名：** 参数约束面向用户的名称。
- **API 名：** 用于引用该参数约束的 API 名。
- 该参数是否必须由实现对象类型映射。

创建参数约束时，你可以手动定义新参数，或从现有接口属性添加参数。从接口属性添加参数会基于所选属性的显示名、类型和必填状态创建参数约束。参数 API 名由显示名生成，并且可以编辑。

![从现有接口属性添加参数。](https://www.palantir.com/docs/resources/foundry/interfaces/iatc-config-dialog-properties.png?width=500)

必填参数约束必须映射到具体动作类型上的必填参数。在适用时，你可以映射可选参数约束。请注意，同一个具体动作参数不能满足同一动作类型约束上的多个参数约束。

对于对象引用、接口引用、对象集和结构体参数，接口动作类型约束描述的是通用参数种类，而非每个具体实现细节。例如，对象引用参数约束要求满足约束的动作类型上有一个兼容的对象引用参数，但该约束本身并不绑定到某个特定对象类型。

## 实现动作类型约束

当对象类型实现一个带有动作类型约束的接口时，该对象类型必须选择满足任何必填约束的具体动作类型。当一个具体动作类型为该约束的必填参数提供了兼容参数时，它即满足该约束。

在 Ontology Manager 中添加接口实现后，对象类型的 **Interfaces**（接口）选项卡会在 **Actions**（动作）子选项卡中列出接口的动作类型约束。为每个必填约束在实现对象类型上选择一个具体动作类型。你可以跳过或映射可选约束。

![接口动作类型约束的对象类型动作映射。](https://www.palantir.com/docs/resources/foundry/interfaces/iatc-mapping-page.png?width=800)

要配置参数映射，选择已映射动作类型约束的设置图标以打开 **Configure parameters**（配置参数）对话框。将每个必填参数约束映射到所选动作类型上兼容的必填参数。当应用需要通过接口动作能力传递或预填这些值时，你也可以映射可选参数约束。

![接口动作类型约束的参数映射。](https://www.palantir.com/docs/resources/foundry/interfaces/iatc-parameter-mapping.png?width=500)

当你保存对本体的更改时，Ontology Manager 会验证动作类型约束映射。在以下情况下，你将无法保存：

- 必填动作类型约束未被实现对象类型映射。
- 必填参数约束未被映射。
- 映射的参数具有不兼容的参数类型。
- 同一个具体动作参数被映射到多个参数约束。
- 映射的动作类型约束或参数约束已不存在。

## 接口扩展

动作类型约束通过[接口扩展](https://www.palantir.com/docs/foundry/interfaces/extend-interface/)继承。如果子接口扩展了一个带有动作类型约束的基础接口，实现子接口的对象类型必须满足继承的必填动作类型约束以及直接在子接口上声明的任何约束。

当某项能力适用于宽泛的接口并应通过更具体的接口提供时，使用继承的动作类型约束。当该能力是该子接口特有时，在子接口上定义新的动作类型约束。

## 选择必填与可选约束

当基于接口的应用需要正常工作、因而每个实现接口的对象类型都必须支持该能力时，应使用必填动作类型约束。

当该能力有用但并非普适时，使用可选动作类型约束。在迭代 beta 版接口模型时，可选约束也很有用，因为它们允许对象类型采用该能力，而不会阻塞尚未准备好支持它的实现。

对于参数约束，仅当每个满足约束的动作类型都必须将该参数作为必填动作输入暴露时，才将参数标记为必填。当各实现可能在内部计算该值、使用默认值或根本不需要该值时，将参数约束保持为可选。

## 限制

接口动作类型约束目前在 Ontology Manager 中配置和映射。Pipeline Builder 目前在实现接口时不支持动作类型约束映射。如果你的接口包含必填动作类型约束，请通过 Ontology Manager 实现和映射该接口。更多平台集成正在活跃开发中。

最终用户目前无法从 Foundry 应用中发现或调用接口动作类型约束。用户可以通过任何支持它们的应用直接运行满足约束的具体动作类型。

Ontology SDK（OSDK）目前不支持接口动作类型约束。你目前无法在 OSDK 中使用接口动作类型约束来发现或调用满足它的具体动作类型。

接口动作类型约束定义了具体动作类型的预期形状。它们不会使对象类型特有的动作逻辑变得统一。请审查每个满足约束的动作类型的规则、提交条件、权限和副作用，以确保它们与接口约束所描述的语义一致。
