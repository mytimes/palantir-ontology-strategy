# 动作日志（Action log）

> 本文为 [Palantir 官方文档](https://www.palantir.com/docs/foundry/action-types/action-log/)的非官方中文翻译，仅供学习参考。原文 © 2026 Palantir Technologies Inc. 保留所有权利。

动作日志将所有动作提交建模为对象类型，以便在对象感知的 Foundry 工具中进行分析和显示。可以将动作日志对象类型用作决策工作流的输入，并监控本体的变更。

> **ℹ️ 提示**
>
> 动作日志旨在捕获通过提交动作所做的决策，并将这些决策作为本体中的数据提供。对于需要记录对象所有编辑的用例，可以为对象类型启用[编辑历史](https://www.palantir.com/docs/foundry/object-edits/user-edit-history/)。

## 背景

动作是修改本体并触发相关副作用的主要方式。这些本体修改通常是特定决策的结果，或伴随着数据审计要求。动作日志简化了表示这些决策和数据编辑的对象类型的生成与维护。为便于识别，所有动作日志对象类型都以 `[LOG]` 为前缀。

## 动作日志本体

动作日志对象类型与动作类型一一对应。提交一个动作会生成相应动作日志对象类型的一个新对象。这个新创建的对象会自动链接到被提交动作编辑的所有对象。通过将日志对象类型与动作类型一一对应建模，动作日志支持捕获特定对象编辑之外的上下文，例如同时编辑了哪些其他对象，以及动作提交时的世界状态（由本体表示）。

例如，设想一个 `Close Alerts`（关闭警报）动作类型，它将许多选中的 `Alert`（警报）对象的“Status”（状态）属性修改为“Closed”（已关闭）。配置动作日志后，一次关闭 10 个 `Alert` 对象将生成一个 `action log` 对象，该对象通过外键链接到全部 10 个 `Alert` 对象。

> **ℹ️ 提示**
>
> 要应用由动作日志支撑的动作类型，用户需要对动作日志对象类型拥有相应权限，就像他们对该动作类型可能通过规则和函数创建或修改的任何其他对象类型一样。

### 动作日志模式

默认情况下，动作日志对象类型存储：

- **动作 RID：**单次动作提交的唯一标识符
- **动作类型 RID：**单个动作类型的唯一标识符
- **动作类型版本：**每次动作类型更新时自动递增的版本号
- **时间戳：**动作提交的 UTC 时间戳
- **UserId：**提交动作用户的 Multipass 用户 ID
- **已编辑对象：**被动作编辑的所有对象的主键值。请注意，不支持存储已编辑对象主键以外的属性。
- [可选] **摘要：**用于描述动作的可自定义字符串
- [可选] **参数值**
- [可选] **对象引用参数的属性值**（如果启用了 `allow multiple values`，则对象引用参数不支持此项）

动作日志对象类型可以配置为存储未被动作编辑的对象属性。这使你既可以存储数据编辑，也可以存储有关本体编辑的上下文或动机的相关信息。

回到 `Close Alerts` 动作类型的示例，设想 `Alert` 对象还有一个“Priority”（优先级）属性，包含“High Priority”（高优先级）和“Low Priority”（低优先级）等值，以及一个“Created at”（创建时间）时间戳和一个“Source”（来源）机器。动作日志支持存储这些属性，即使它们没有被 `Close Alerts` 编辑。通过对“Priority”进行聚合，无需编辑该列，我们就可以回答诸如“大多数‘高优先级’警报的来源在哪里？”或“关闭‘高优先级’警报需要多长时间？”之类的问题。

## 函数支撑的动作类型上的动作日志

要为函数支撑的动作类型配置动作日志，其支撑的本体编辑函数必须配置了 `Edits` 溯源（provenance）。有关 `Edits` 溯源的更多信息，请参阅[函数文档](https://www.palantir.com/docs/foundry/functions/edits-overview/)。

## 动作日志时间线

你可以使用自定义 Workshop 组件在时间线中查看动作日志对象类型。借助该组件，可以配置时间线以支持数据审计，帮助回答“什么发生了变更、由谁变更、何时变更？”的问题。

在 Workshop 中，可以将多个动作日志对象类型联合在一起，以全面查看某个用例内或整个本体中的编辑情况。

配置动作日志时间线时，先选择被编辑的对象类型。然后选择要显示哪些动作日志对象类型，以及所需的动作日志对象类型属性。
