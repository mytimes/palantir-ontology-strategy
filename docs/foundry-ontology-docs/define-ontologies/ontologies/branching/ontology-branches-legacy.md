# 本体提案（旧版）（Ontology proposals [Legacy]）

> 本文为 [Palantir 官方文档](https://www.palantir.com/docs/foundry/ontologies/ontology-branches-legacy/)的非官方中文翻译，仅供学习参考。原文 © 2026 Palantir Technologies Inc. 保留所有权利。

> **⚠️ 注意**
>
> 本体分支（以前称为本体提案）正在停止服务。在启用了全局分支化的注册实例上，你无法再创建本体分支。请改用[全局分支](https://www.palantir.com/docs/foundry/ontologies/branching-ontology/)来修改本体，并使用更多扩展功能，包括分支化数据源、在下游受支持的应用中测试更改，以及在统一工作流中管理数据和本体修改。

本体分支允许你在分支上对本体进行更改，该分支基于该本体的 `Main`（主）版本。此过程确保所有修改在合并到主本体之前都经过评审和批准。

要创建分支，你需要对包含资源的项目拥有编辑者权限。

## 定义

- **分支：** 本体上的*分支*是该本体的独立版本，派生自主版本，旨在支持实验和更改而不影响主分支。这允许用户在隔离环境中测试和优化对本体的调整，然后再将它们合并回主分支。
- **提案：** *提案*类似于版本控制系统中的拉取请求（Pull Request），专门为本体分支定制。提案会与分支一起自动创建，并包含元数据，例如评审、名称以及要合并到主分支的更改的描述。提案是一种机制，用于在将单独分支中所做的更改集成到主本体之前，对其进行评审和批准。

## 本体分支化工作流

本体分支化的一般工作流有五个步骤：

1. [创建你的分支](#1-创建你的分支)
2. [准备你的提案以供评审](#2-准备你的提案以供评审)
3. [请求评审](#3-请求评审)
4. [评审提案](#4-评审提案)
5. [发布提案](#5-发布提案)

以下各节将概述每个步骤。

### 1. 创建你的分支

你可以通过选择 **Create Branch**（创建分支）来创建分支，这会打开一个对话框，你可以在其中为提案选择标题和描述。

或者，如果你已经对本体进行了更改并希望将其包含在提案中，可以在保存对话框中选择保存并切换 **Propose your changes**（提议你的更改）。

![提议你的更改。](https://www.palantir.com/docs/resources/foundry/ontologies/propose-changes.png)

如果你在本体的主分支上且没有任何更改，你也可以通过选择分支选择组件并为新分支键入名称来创建分支。

提案分支只能在主本体配置上创建。你不能基于另一个提案创建新分支。

在分支上工作时，工作区界面上方的分支导航顶部栏会显示你当前所在的分支。

![分支导航顶部栏。](https://www.palantir.com/docs/resources/foundry/ontologies/topbar.png)

### 2. 准备你的提案以供评审

此时，根据你创建提案的方式，你的分支上可能已经有一些更改。在分支上，你可以继续对本体资源进行更改，包括创建和删除。

每个被修改的本体实体将在你的提案中构成一个单独的**任务（Task）**，并可供评审。

对于已迁移为使用[本体角色](https://www.palantir.com/docs/foundry/object-permissioning/ontology-permissions-legacy/#ontology-roles)的资源，查看者可以在提案中对资源进行更改。如果资源使用基于数据源派生的权限，则只有编辑者或所有者可以在提案中对其进行更改。

> **ℹ️ 提示**
>
> 在分支上，你可以在持有编辑者或所有者权限时编辑资源。

### 3. 请求评审

在对分支进行更改后，你可以向提案添加评审者。为此，通过选择顶部栏中的 **Open proposal details**（打开提案详情）导航到你的[提案视图](#2-准备你的提案以供评审)。

如果你已退出分支，可以通过导航到 **Proposals**（提案）选项卡并选择你的提案，或使用分支选择组件，来转到你的提案概览。

在那里，从 **Reviewers**（评审者）部分分配评审者。

在提案进入 `In review`（评审中）阶段之前，评审者不会收到通知。

> **ℹ️ 提示**
>
> 你还可以对提案中的各个任务发表评论，以提供有关所提议更改的上下文。选择 **Reviews**（评审）选项卡，然后选择最右侧的 **Comments**（评论）侧边栏，即可访问任务的**评论**部分。

### 4. 评审提案

评审者可以在 **Reviews**（评审）选项卡中批准或拒绝单个任务，并可以添加评论来支持其评审。

评审者必须拥有所有者或编辑者权限才能批准更改。

没有权限的用户仍然可以评审任务（例如，表达他们对更改的意见），但这不会影响任务的批准状态。

如果提案的创建者对所有已编辑资源拥有所有者或编辑者权限，他们将能够批准自己的更改。

> **⚠️ 注意**
>
> 即使编辑者或所有者未被明确添加为评审者，他们仍然可以批准你的提案。我们建议使用评审者列表来跟踪谁应该评审更改，而不是将其作为保护本体的手段。相反，应通过谨慎分配角色和权限来保护本体。

### 5. 发布提案

更改经过评审和批准后，提案即可合并到本体中。

> **ℹ️ 提示**
>
> 将更改合并到本体不需要特殊权限。提案获得批准后，任何可以编辑该分支的人都可以将提案合并到本体中。

提案合并后，它会从侧边栏的 **In Review**（评审中）部分移动到 **Merged**（已合并）部分。

在合并提案之前的任何时候，你都可以通过从侧边栏选择 **delete**（删除）来关闭提案。

提案只能合并到主本体配置中。

提案无法自动撤销。要撤销提案，你必须撤销其中包含的各项更改。

> **⚠️ 注意**
>
> 提案一旦关闭，将无法重新打开。
