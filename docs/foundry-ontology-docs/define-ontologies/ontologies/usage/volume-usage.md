# 本体用量（Ontology volume usage）

> 本文为 [Palantir 官方文档](https://www.palantir.com/docs/foundry/ontologies/volume-usage/)的非官方中文翻译，仅供学习参考。原文 © 2026 Palantir Technologies Inc. 保留所有权利。

Foundry 的本体是一个快速访问存储层，允许你将对象定义绑定到交互式数据，用于查询、链接、场景和动作。Foundry 本体中的数据会被编入索引，以实现快速访问，并支持多个编辑者同时安全编辑。本体用量是对已编入索引的对象集及其相互链接的总大小的度量。本体用量是一个平均指标：瞬时读数的单位为 GB，而度量一个月期间的用量时单位为 GB-月（GB-Month）。

## 度量本体用量

本体用量通过度量支撑对象类型的索引大小来记录。每个对象类型有若干对象，每个对象有若干属性。每个属性可以是任意大小。索引的总大小通过对该对象类型的每个对象的每个已编入索引属性的大小求和来计算。

> **ℹ️ 提示**
>
> 值得注意的是，本体用量可能大于数据集用量，因为本体数据无法压缩，而且本体索引构建需要额外的存储来支持更快的查询。

Foundry 平台每小时记录一次每个对象的本体用量测量值。随时间度量本体用量时，所有每小时测量值会在给定时间段内取平均。在一个日历月内取平均即产生 *GB-月* 单位。

## 调查本体用量

对象在 Ontology Manager 中管理，它是所有对象管理和监控的中心。Ontology Manager 允许用户配置哪些数据集应成为对象、这些对象上附加哪些类型的属性，以及在对象类型之间定义哪些链接集。

对象及其对应链接类型的本体总用量列在资源管理应用（Resource Management Application）中。

## 本体用量的驱动因素

本体用量实际上是对本体中所有对象（包括其属性和链接）大小的度量。以下两个因素是总用量的主要驱动因素。

- **每个对象类型的对象数量和大小**
  - 从数据集创建本体对象类型时，该数据集的每一行都会有一个对象被编入索引。因此，该数据集中的行数与对应对象类型中的对象数量是 1:1 绑定的。
  - 此外，具有更多列或包含更多数据的数据集（例如自由文本字段）可能产生更大的单个对象，因为每一列都会变成一个属性。
- **使用连接表时对象之间的链接数量**
  - 在多对多关系中，本体需要定义一个连接表（join table），以根据主键定义对象之间的所有链接。这些表与本体中的对象一起被编入索引，并消耗本体用量。
  - 一般而言，查找表每条记录的大小恒定，其用量随所定义链接的数量线性增长。

## 管理本体用量

本体被设计为用于运营使用和查询的快速访问后端。在一般情况下，本体最适合用于从更大的数据资产综合而来的高度精炼数据。因此，本体的用量应当小于 Foundry 转换框架中原始数据和中间数据的总大小。

要管理本体用量，请关注本体中定义的对象类型数量，以及每个对象类型的对象数量和每个对象的属性数量。总体而言，管理本体用量的最佳方式是理解并有意识地管理对象数量、属性数量和属性大小。
